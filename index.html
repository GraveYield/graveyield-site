The problem

The liquidity stays. The market leaves.

When a memecoin dies, its pool keeps the valuable side: SOL, USDC or USDT. Holders rarely recover it. The frontend is gone and the position looks too small to chase.

How it works

Certify. Salvage. Settle.

Evaluation and execution are separate programs, so no single path can both declare a pool derelict and move its funds.

01

Certify

GraveScanner checks six criteria, records an anchor, and issues a certificate only after two consecutive epochs. It never moves liquidity.

02

Salvage

GraveVault withdraws from Raydium V4 and swaps through Jupiter in one atomic transaction. If any check fails, everything reverts.

03

Settle

Proceeds are split by formula. LP holders claim with a Merkle proof from an unsweepable vault, with no expiry.

Security

What governance cannot change.

Four invariants are enforced in program bytecode. Changing one needs a program upgrade, itself gated by public notice, a timelock and multisig process.

Bytecode

The 20% share is a ceiling

A config update that tries to raise it is rejected with error 7005.

Bytecode

The LP vault is unsweepable

No sweep instruction exists in v1.0, for any admin key.

Bytecode

Claims survive an emergency pause

Holders can always claim from a completed salvage.

Bytecode

One settlement per pool, ever

A second attempt fails at account initialization.

Process commitments, enforced by the multisig and the public record: no token at any layer, 72-hour timelocks on parameter changes, 7-day notice for standard upgrades, and Squads multisig custody (3-of-5 at launch). Read all ten invariants ↗
